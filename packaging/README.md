# Packaging

Scripts that collect the built Retrace artifacts into native installers. Build the project first
(`just build` or `cmake --build build/<platform> --config Release --target retrace`), then run the
packaging recipe for your platform. Each script ships everything it finds: every plugin format and
the standalone application. All installers are written to the top-level `dist/` directory.

```
packaging/
├── common.sh                 # Shared config + artifact discovery (sourced by the *.sh scripts)
├── common.ps1                # Shared config for the PowerShell scripts (Windows)
├── icons/generate_icons.sh   # Generate app-icon.icns / app-icon.ico from assets/app-icon.png
├── macos/build_pkg.sh        # Build a macOS .pkg installer
├── linux/build_archive.sh    # Build a Linux .tar.gz
├── linux/build_deb.sh        # Build a Debian .deb package
├── linux/app.desktop.in      # Desktop entry of the standalone application
├── android/build_apk.sh      # Collect the Android .apk from the Gradle build
├── ios/build_ipa.sh          # Package the iOS .app into an .ipa
├── wasm/build_archive.sh     # Build a WebAssembly .tar.gz
└── windows/
    ├── installer.iss         # Inno Setup script
    └── build_installer.ps1   # Helper that invokes ISCC with the right defines
```

## Usage

```bash
just icons               # regenerate the platform icons (optional)
just package-macos       # macOS .pkg from build/mac
just package-linux       # Linux .tar.gz + .deb from build/linux
just package-win         # Windows installer from build/win
just package-wasm        # WebAssembly .tar.gz from build/emscripten
just package-macos Debug # ...from a specific build configuration
```

Or call the scripts directly. They accept `[CONFIG] [BUILD_DIR]` and honour the overrides below.
`BUILD_DIR` defaults to the `build/<platform>` folder generated by the matching `just` recipe:

```bash
packaging/macos/build_pkg.sh Release                 # build/mac
packaging/linux/build_archive.sh Release             # build/linux
packaging/linux/build_deb.sh Release                 # build/linux
packaging/android/build_apk.sh Release               # build/android
packaging/ios/build_ipa.sh Release                   # build/ios
packaging/wasm/build_archive.sh Release              # build/emscripten
pwsh packaging/windows/build_installer.ps1 -Config Release   # build\win
```

The mobile scripts package the outputs of the respective platform builds: run the
Android Gradle build (`./gradlew assemble`) or the iOS CMake build first, then the
script copies the `.apk` / `.ipa` file into `dist/`. Both the Android and iOS CI
workflows run these automatically and upload the result as a build artifact (and
attach it to a tagged GitHub Release). The generated `.ipa` is **unsigned** — fine
as an artifact, but device installation still requires code signing.

## Install locations

| Format | macOS | Linux | Windows |
|--------|-------|-------|---------|
| VST3 | `/Library/Audio/Plug-Ins/VST3` | `/usr/lib/vst3` | `%CommonProgramFiles%\VST3` |
| CLAP | `/Library/Audio/Plug-Ins/CLAP` | `/usr/lib/clap` | `%CommonProgramFiles%\CLAP` |
| AU   | `/Library/Audio/Plug-Ins/Components` | — | — |
| LV2  | `/Library/Audio/Plug-Ins/LV2` | `/usr/lib/lv2` | `%CommonProgramFiles%\LV2` |
| AAX  | `/Library/Application Support/Avid/Audio/Plug-Ins` | — | `%CommonProgramFiles%\Avid\Audio\Plug-Ins` |
| Standalone | `/Applications` | `/usr/bin` (+ `.desktop`) | `%ProgramFiles%\<Company>\<Product>` |

The scripts glob the build tree by file extension, and look up the standalone executable by the
product name (`PRODUCT_NAME`), so only what you actually built is included. Missing artifacts are
skipped with a warning. The WebAssembly archive stages the standalone into its own folder, with a
top-level `index.html` that opens it.

The Audio Unit v3 app extension is built but not packaged: it has to ship inside a signed container
application.

AAX is only built when the Avid SDK is available (`YUP_AAX_SDK_ROOT`). The installers ship the AAX
bundle as built; Pro Tools release builds additionally need it signed with PACE's `wraptool` before
packaging, which these scripts don't do.

## Requirements

- **macOS**: `pkgbuild` / `productbuild` (Xcode command line tools). `sips` + `iconutil` for icons.
- **Linux**: `dpkg-deb` for `.deb`. `tar` for the archive.
- **Windows**: [Inno Setup 6](https://jrsoftware.org/isinfo.php) (`ISCC.exe`). ImageMagick to
  regenerate the `.ico`.

## Customisation & overrides

Product naming is **inherited from `CMakeLists.txt`** — `common.sh` (bash) and `common.ps1`
(PowerShell) parse the project configuration block for `PROJECT_NAME`, `PRODUCT_NAME`,
`PRODUCT_DESCRIPTION`, `COMPANY_NAME`, `BUNDLE_ID`, `PRODUCT_URL` and `PRODUCT_EMAIL`, and the
version comes from the `VERSION` file. Nothing has to be kept in sync by hand: change a value in
CMake and every installer follows.

Override any value, plus the build/output locations, via environment variables:

```bash
BUILD_DIR=/path/to/build DIST_DIR=/tmp/out \
  packaging/macos/build_pkg.sh Release
```

### Signing & notarization

The default build is **unsigned** — every signing step is skipped unless you provide credentials, so
the project builds out of the box. Provide the values below to opt in.

#### macOS

`packaging/macos/build_pkg.sh` reads these environment variables:

| Variable | Purpose |
|----------|---------|
| `APPLICATION_SIGNING_IDENTITY` | `Developer ID Application: ...` — codesigns the plugin and application bundles with the hardened runtime. |
| `INSTALLER_SIGNING_IDENTITY` | `Developer ID Installer: ...` — signs the `.pkg`. Required before notarization. |
| `NOTARY_KEYCHAIN_PROFILE` | A stored `notarytool` keychain profile, **or**… |
| `NOTARY_APPLE_ID` / `NOTARY_TEAM_ID` / `NOTARY_PASSWORD` | …an Apple ID + Team ID + app-specific password triple. |

Notarization (`xcrun notarytool submit --wait` + `xcrun stapler staple`) runs only when the installer
is signed **and** notarization credentials are present.

In CI (`.github/workflows/build_macos.yml`) set these repository secrets to enable signing:
`APPLE_DEVELOPER_ID_CERT_P12` (base64 of the exported `.p12`), `APPLE_DEVELOPER_ID_CERT_PASSWORD`,
`APPLE_APPLICATION_IDENTITY`, `APPLE_INSTALLER_IDENTITY`, and for notarization
`APPLE_NOTARY_APPLE_ID`, `APPLE_NOTARY_TEAM_ID`, `APPLE_NOTARY_PASSWORD`.

#### Windows

`INSTALLER_GUID` in `CMakeLists.txt` identifies the installed product: keep it stable, so an upgrade
replaces the previous installation. CI
(`.github/workflows/build_windows.yml`) signs the installer with
[Azure Trusted Signing](https://learn.microsoft.com/azure/trusted-signing/) when these repository
secrets are set: `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`,
`AZURE_SIGNING_ENDPOINT`, `AZURE_SIGNING_ACCOUNT`, `AZURE_SIGNING_CERT_PROFILE`. To sign locally
instead, use `signtool` against `dist/*.exe`.
